## What's Changed

### 新增

- LLM 钩子装饰器（`@on_llm_request`、`@on_llm_response`、`@on_llm_tool_respond`、`@on_using_llm_tool`、`@on_agent_begin`、`@on_agent_done`）新增可选关键字参数 `fail_closed` 与 `timeout_seconds`。`fail_closed=True` 在钩子抛异常或超时时中止整个管道：调用 `event.stop_event()`、抑制用户回复、跳过对话历史追加，并通过 `event.trace.record("hook_failure", ...)` 记录稳定的错误码 `ASTRBOT_HOOK_FAIL_CLOSED`，便于运维告警。`timeout_seconds=N` 通过 `asyncio.wait_for` 实现按钩子超时。默认行为保持不变。新增配置项 `pipeline.hook_failure_metric_name`（默认 `astrbot.hook.fail_closed`）用于自定义指标名。同步修复：`KeyboardInterrupt` 与 `SystemExit` 不再被钩子调度的 `except BaseException` 静默吞掉。

<a id="english"></a>

## What's Changed (EN)

### New Features

- LLM hook decorators (`@on_llm_request`, `@on_llm_response`, `@on_llm_tool_respond`, `@on_using_llm_tool`, `@on_agent_begin`, `@on_agent_done`) now accept optional `fail_closed` and `timeout_seconds` kwargs. `fail_closed=True` aborts the pipeline cleanly on a handler exception or timeout: `event.stop_event()` is called, the user-facing reply is suppressed, conversation history is not appended, and a structured audit is emitted via `event.trace.record("hook_failure", ...)` together with a stable `ASTRBOT_HOOK_FAIL_CLOSED` error code for operator alerting. `timeout_seconds=N` is implemented with stdlib `asyncio.wait_for`. Default behavior is unchanged. A new config knob `pipeline.hook_failure_metric_name` (default `astrbot.hook.fail_closed`) lets operators customize the audit metric name. Drive-by fix: `KeyboardInterrupt` and `SystemExit` are no longer swallowed by the hook dispatcher's `except BaseException`.
